## 4. 階層型委譲アクセス制御（Delegated RBAC）ロジック仕様

### 4.1 認可マトリクス判定ロジック
```python
def check_user_management_permission(
    operator_role: str,
    target_role: Optional[str] = None,
    new_role: Optional[str] = None,
) -> None:
    # 1. 最低限の管理権限チェック
    if operator_role not in (RoleType.ADMIN.value, RoleType.EDITOR.value):
        raise PermissionError("ユーザー管理には管理者（Admin）または編集長（Editor）権限が必要です。")

    # 2. 最高管理者の場合は全操作可能
    if operator_role == RoleType.ADMIN.value:
        return

    # 3. 編集長（Editor）の場合の安全ガード
    if operator_role == RoleType.EDITOR.value:
        # ガードA: 上位階層保護（管理者アカウントの操作禁止）
        if target_role == RoleType.ADMIN.value:
            raise PermissionError("編集長権限で管理者（Admin）アカウントを操作することはできません。")

        # ガードB: 権限昇格の禁止（管理者ロールの付与禁止）
        if new_role == RoleType.ADMIN.value:
            raise PermissionError("編集長権限で管理者（Admin）ロールを付与することはできません（権限昇格禁止）。")
```

### 4.2 WebUI側の多層防御（Defense-in-Depth）
* **タブ表示制御**: ログインユーザーのロールが `editor` または `admin` の場合、`tab-users`（ユーザー・権限管理）のロックを解除。
* **テーブル表示制御**: 操作対象が `role === 'admin'` かつログインユーザーが `role !== 'admin'` の場合、編集・PW・停止・削除ボタンを非表示にし、代わりに `<span class="badge-role-locked">🔒 管理者保護</span>` を描画。
* **モーダル選択肢制御**: `editor` ログイン時は、ユーザー作成・編集モーダルの役職ドロップダウンから `admin` オプションを除外。新規作成時は編集長の所属部署名を自動プリセット。

## 5. ブルートフォース総攻撃防護＆セッションアイドルタイムアウト技術仕様

### 5.1 アカウントロックアウト（Account Lockout）制御ロジック
* **DBテーブル拡張 (`users`)**:
  * `failed_attempts INTEGER DEFAULT 0`: 連続認証失敗カウンター
  * `locked_until REAL DEFAULT 0`: ロック終了時刻（UNIXタイムスタンプ）
* **認証試行アルゴリズム (`RBACManager.authenticate`)**:
  ```python
  # 1. ユーザー存在チェック & 利用停止（is_active）チェック
  # 2. ロックアウト状態チェック
  now = time.time()
  if row["locked_until"] and now < row["locked_until"]:
      remaining = int(row["locked_until"] - now)
      minutes, seconds = divmod(remaining, 60)
      raise AccountLockedError(
          f"アカウントは一時的にロックされています。5分後に再度お試しいただくか、管理者にお問い合わせください。（残り解除時間: 約{minutes}分{seconds}秒）"
      )
  
  # 3. パスワード照合
  if not verify_password(password, row["password_hash"]):
      new_fails = row["failed_attempts"] + 1
      locked_until = (now + 300) if new_fails >= 5 else 0
      # DB更新: failed_attempts = new_fails, locked_until = locked_until
      if new_fails >= 5:
          raise AccountLockedError("パスワード試行回数の上限（5回）を超えたため、アカウントを5分間ロックしました。")
      return None

  # 4. 認証成功時: 失敗カウンターリセット
  # DB更新: failed_attempts = 0, locked_until = 0
  ```
* **即時アンロック (`RBACManager.unlock_user`)**:
  * `operator_role` による階層型委譲アクセス制御（EditorはAdminアカウントをアンロック不可）。
  * 対象ユーザーの `failed_attempts = 0`, `locked_until = 0` を即時反映。

### 5.2 セッション無操作アイドルタイムアウト制御ロジック
* **`UserSession` クラス拡張**:
  ```python
  @dataclass
  class UserSession:
      session_id: str
      username: str
      display_name: str
      role: str
      department: str
      created_at: float = field(default_factory=time.time)
      expires_at: float = field(default_factory=lambda: time.time() + 86400)  # 24時間上限
      last_activity_at: float = field(default_factory=time.time)             # 最終操作時刻

      def touch(self) -> None:
          """APIリクエスト受付時に呼び出し、アイドルタイマーを更新"""
          self.last_activity_at = time.time()

      def is_expired(self, max_idle_seconds: float = 1800) -> bool:
          """24時間上限または30分無操作で失効判定"""
          now = time.time()
          if now > self.expires_at:
              return True
          if (now - self.last_activity_at) > max_idle_seconds:
              return True
          return False
  ```




## 多言語化（i18n）技術仕様（REQ-036 / DES-024）

* **ファイル**：`src/web/static/i18n.js`（`index.html` で `app.js` より前に読込）。
* **データ構造**：`translations = { ja: {key: text}, en: {...}, 'zh-TW': {...} }`。3言語のキー集合は一致必須（TEST-053-02で検証）。
* **API**：
  ```javascript
  i18n.t(key, params)      // {name} 等のプレースホルダ置換。未定義はja→keyの順にフォールバック
  i18n.setLanguage(lang)   // localStorage('gcomm_lang') 保存 + updateDOM() + CustomEvent('languageChanged')
  i18n.updateDOM()         // data-i18n / data-i18n-html / data-i18n-placeholder / data-i18n-title を一括置換
  ```
* **初期化**：`app.js` の `DOMContentLoaded` で保存言語を復元し `updateDOM()` を実行。
* **フレーズテーブル**：`src/web/static/i18n_phrases.js`（`window.I18N_PHRASES` / `window.I18N_PATTERNS`）。`i18n.tr(text)` は完全一致→正規表現の順で翻訳、未一致は原文返却。`/i18n.js`・`/i18n_phrases.js` は未ログイン時も取得できるよう `scripts/start_web.py` の公開静的アセットに追加。
* **CSS**：`.lang-select`、`:lang(zh-TW)` / `:lang(en)` のフォント・折り返し規則を `style.css` に追加。
* **セキュリティ**：辞書は静的自社データのみ。`data-i18n-html` は辞書値のみを対象とし、ユーザー入力は使用しない。

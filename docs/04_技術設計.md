## 4. 階層型委譲アクセス制御（Delegated RBAC）ロジック仕様

### 4.1 認可マトリクス判定ロジック
```python
def check_user_management_permission(
    operator_role: str,
    target_role: Optional[str] = None,
    new_role: Optional[str] = None,
) -> None:
    # 1. 最低限の管理権限チェック
    if operator_role not in (RoleType.ADMIN.value, RoleType.EDITOR.value):
        raise PermissionError("ユーザー管理には管理者（Admin）または編集長（Editor）権限が必要です。")

    # 2. 最高管理者の場合は全操作可能
    if operator_role == RoleType.ADMIN.value:
        return

    # 3. 編集長（Editor）の場合の安全ガード
    if operator_role == RoleType.EDITOR.value:
        # ガードA: 上位階層保護（管理者アカウントの操作禁止）
        if target_role == RoleType.ADMIN.value:
            raise PermissionError("編集長権限で管理者（Admin）アカウントを操作することはできません。")

        # ガードB: 権限昇格の禁止（管理者ロールの付与禁止）
        if new_role == RoleType.ADMIN.value:
            raise PermissionError("編集長権限で管理者（Admin）ロールを付与することはできません（権限昇格禁止）。")
```

## 5. セキュリティ堅牢化・脆弱性防御技術仕様（REQ-037 / DES-025）

### 5.1 Google OIDC IDトークン暗号署名検証
* `google.oauth2.id_token.verify_oauth2_token(token, requests.Request(), client_id)` を用い、Google公開鍵（JWKS）のRSA署名を暗号学的に検証。
* 未署名JWT（`alg: none`）や不正署名トークンは `InvalidTokenError` で即座に遮断。

### 5.2 フロントエンド Stored DOM XSS 対策
* 管理画面のHTML生成において、`onclick="openModal('${u.username}')"` 等の文字列埋め込みを完全排除。
* `data-username="${escapeHtml(u.username)}"` 属性およびコンテナ要素へのイベントデリゲーション（`addEventListener('click', ...)`）を採用。

### 5.3 タイミング攻撃対策（ユーザー列挙防止）
* `RBACManager.authenticate` において、存在しないユーザー名が指定された場合でも固定ダミーハッシュに対する `verify_password(password, DUMMY_HASH)` を実行し、PBKDF2計算時間（約10〜20ms）を等しく消費させることで、応答時間差による実在アカウント特定を遮断。

### 5.4 リクエストペイロードサイズ制限
* `PortalRequestHandler._read_json_body` で `Content-Length` を検証。`MAX_PAYLOAD_SIZE`（25MB）を超えるリクエストは `HTTPStatus.REQUEST_ENTITY_TOO_LARGE` (413) で即座に破棄し、サーバーOOMクラッシュを防止。

### 5.5 セキュリティヘッダー
* 全HTTPレスポンスに以下のヘッダーを注入：
  * `Content-Security-Policy`: `default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;`
  * `Permissions-Policy`: `geolocation=(), microphone=(), camera=()`
  * `X-Content-Type-Options`: `nosniff`
  * `X-Frame-Options`: `DENY`
  * `X-XSS-Protection`: `1; mode=block`

## 6. 大企業NAT対応・動的レート制限技術仕様（REQ-038 / DES-026）

### 6.1 ログインAPIスライディングウィンドウ制限
* 制限値: `rate_limit_login`（デフォルト 20回/分/IP）。
* 移動窓（60秒）内のタイムスタンプを追跡し、超過時は `Retry-After: <秒数>` を返却。

### 6.2 チャットAPIのアカウント単位分離
* 制限値: `rate_limit_chat`（デフォルト 60回/分/アカウント、`0` で無制限）。
* スロットリングキー: `session.username`（ログインアカウント名）。10,000人の社員が同一の社内NAT IP（X-Forwarded-For）を共有している場合でも、社員A・B・Cそれぞれに独立したバケットが割り当てられ、巻き添え遮断を完全に防止。

### 6.3 クライアントIP抽出ロジック (`_get_client_ip`)
```python
def _get_client_ip(self) -> str:
    xff = self.headers.get("X-Forwarded-For")
    if xff:
        client_ip = xff.split(",")[0].strip()
        if client_ip:
            return client_ip
    return self.client_address[0]
```

### 6.4 管理画面からの動的設定管理
* `system_settings.json` の `rate_limit_login` および `rate_limit_chat` を `/api/v1/settings`（POST）で動的更新可能。サーバー再起動不要で即時反映。

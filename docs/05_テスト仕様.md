## 3. テスト実施仕様詳細（追加テストケース）

### 3.7 TEST-033：[入社時] 新規社員アカウント登録・入力検証・初期PW発行
* **目的**：入社手続きにおいて、管理者が新しい社員アカウントを安全かつ正確に発行できることを担保する。
* **テスト手順**：
  1. 非管理者（Viewer）でユーザー作成を試み、`PermissionError` で拒絶されることを確認。
  2. 不正な文字種（空白や全角文字等）を含むIDで登録を試み、バリデーション例外を検証。
  3. 正常な情報（`yamada_t`、氏名、部署、役職 `viewer`、初期PW）で登録し、`is_active=True` で作成されることを確認。
  4. 同一IDでの二重登録を試み、重複エラー（一意性制約）が送出されることを検証。
  5. 作成された初期パスワードでログインし、Viewer権限が正常に付与されていることを確認。
* **合格判定**：正常登録率 100%、不正入力・非権限アクセスの遮断率 100%。

### 3.8 TEST-034：[異動・昇格時] 役職変更・部署変更・管理者PW再発行
* **目的**：人事異動や昇格に伴い、権限や所属部署の変更、およびパスワード忘れ時の安全なリセットを担保する。
* **テスト手順**：
  1. 社員 `suzuki_j` の役職を `viewer` から `editor` に昇格し、部署を更新。
  2. 昇格後のログインを行い、`knowledge:write` 権限が即座に付与されていることを検証。
  3. 管理者が `reset_user_password` を実行し、新しいパスワードを設定。
  4. 旧パスワードでのログインが拒絶され、新パスワードでのみログイン成功することを検証。
* **合格判定**：権限昇格の即時反映、旧PW無効化および新PW認証の完全性。

### 3.9 TEST-035：[休職・退社時] 即時利用停止・アクティブセッション即時破棄・利用再開
* **目的**：退職や休職に際し、過去の監査ログを保持したまま即時にアクセスを遮断し、セッションを強制終了できることを担保する。
* **テスト手順**：
  1. 社員 `mori_s` がログインし、アクティブなセッショントークンを保持している状態にする。
  2. 管理者が `toggle_user_status` で `is_active=False`（利用停止）を実行。
  3. `mori_s` が所持していたアクティブセッショントークンが即座に無効化（破棄）され、業務APIへアクセスできないことを検証。
  4. `mori_s` が再度ログインを試みた際、停止中メッセージとともにログインが拒絶されることを確認。
  5. 管理者が `is_active=True`（利用再開）を実行後、再び正常にログインできることを検証。
* **合格判定**：利用停止時のアクティブセッション切断率 100%、再開時の正常復帰 100%。

### 3.10 TEST-036：エンタープライズ安全ガード（自己削除防止・最後のAdmin保護・完全削除）
* **目的**：操作ミスによる自己アカウントの誤削除や、管理者が0名になるシステムロックアウト事故を完全に防止する。
* **テスト手順**：
  1. ログイン中の管理者自身のアカウントに対して利用停止および削除を実行し、安全ガードにより例外送出されることを検証。
  2. システム内に有効な管理者が1名しかいない状態で、Adminの削除・降格・停止を試み、ロックアウト防止ガードが作動することを検証。
  3. 削除対象の一般社員アカウントに対して完全削除を実行し、DBから消去され関連セッションが破棄されることを確認。
* **合格判定**：自己削除・自己停止・ラストAdmin削除の完全遮断。

### 3.11 TEST-037：ユーザー情報＆ステータスのSQLite完全永続化検証
* **目的**：サーバー再起動やプロセス停止後も、登録した社員情報や役職、停止状態が確実に保持・復元されることを担保する。

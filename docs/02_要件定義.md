## 3. 追加要件の詳細と受入条件（Acceptance Criteria）

### REQ-008: クラウドGeminiハイブリッド推論
* **入力**：ユーザープロンプト、モデル指定（例: `gemini-2.0-flash`, `gemini-1.5-pro`）、APIキー
* **処理**：`InferenceEngine` に `provider="gemini"` を指定した場合、Google公式 `google-genai` SDK を通じてクラウドAPI推論を実行。未設定またはオフライン時はローカルLiteRT-LMで実行。
* **出力**：Geminiからの生成回答テキスト（ストリーミング対応）
* **受入条件**：
  * **AC-008-01**：`provider="gemini"` 指定時にGoogle GenAI APIクライアントを通じて回答が取得できること。
  * **AC-008-02**：APIキー未設定時またはオフライン時に適切な案内またはローカルモデルへのフォールバックが行われること。

### REQ-009: 文境界優先チャンキング
* **入力**：長文テキスト（日本語/英語）、目標チャンクサイズ（例: 500〜1200字）、オーバーラップ長
* **処理**：指定文字数の 65%〜100% の探索ウィンドウ内で、句点「。」「！」「？」および改行記号「\n\n」「\n」を探索して分割点を決定。各チャンクに見出しや位置情報（`locator`）を付与。
* **出力**：`ChunkDraft` オブジェクトのリスト
* **受入条件**：
  * **AC-009-01**：文の途中ではなく句点または改行でチャンクが分割されること。
  * **AC-009-02**：各チャンクに正確な文字オフセットと位置識別子（`locator`）が保持されること。

### REQ-010: ナレッジブロックCMS（部分文面CRUD）
* **入力**：ブロックID、更新後テキスト、新規追加テキスト、削除対象ブロックID
* **処理**：
  * **追加 (Create)**：新しい文面ブロックを登録し、即座にベクトル化してストアへ格納。
  * **取得 (Read)**：キーワードや文書IDでブロック一覧を検索・取得。
  * **更新 (Update)**：特定ブロックの文面のみを書き換え、該当ブロックのベクトルのみをミリ秒で再計算・置換。
  * **削除 (Delete)**：特定ブロックをベクトルストアから即座に削除。
* **受入条件**：
  * **AC-010-01**：部分文面を更新した直後の検索において、更新後の内容が即座にヒットし、古い内容がヒットしないこと。
  * **AC-010-02**：ブロック削除後に該当内容が検索対象から完全に除外されること。

### REQ-011: 人間中心設計（HCD）WebUI
* **入力**：ブラウザからのユーザー操作（クリック、ドラッグ＆ドロップ、テキスト入力）
* **処理**：
  * 明快な5大タブ構成：
    1. 💬 **社内アシスタント（チャット）**：ChatGPT互換、厳選1行出典リンク表示。
    2. 📁 **ファイル追加**：D&D対応、自動解析・自動チャンキング。
    3. ✏️ **ナレッジ文面編集**：カード型ブロックエディタで部分修正・即時保存。
    4. 🔍 **検索テスト（シミュレーター）**：質問文に対するヒットチャンクとスコアの可視化。
    5. ⚙️ **モデル設定**：ローカル（LiteRT-LM）とクラウド（Gemini API）のワンタッチ切替。
* **受入条件**：
  * **AC-011-01**：WebUIが単一ポート（FastAPI内包）で起動し、ブラウザから主要5機能が正常に操作できること。
  * **AC-011-02**：ボタンや操作ごとに成功トースト通知・エラー通知が表示され、直感的に状況が把握できること。

### REQ-012: MCP (Model Context Protocol) サーバー
* **入力**：外部AIからの JSON-RPC 2.0 リクエスト
* **処理**：`tools/list` によるナレッジ検索ツールの公開、および `tools/call`（`search_knowledge`）によるRAG検索実行。
* **出力**：構造化JSON-RPCレスポンス
* **受入条件**：
  * **AC-012-01**：`tools/list` リクエストに対し、ナレッジ検索ツールの仕様が正常に返却されること。
  * **AC-012-02**：`tools/call` リクエストに対し、社内ナレッジを検索した結果テキストが返却されること。

### REQ-034: 大企業向け階層型委譲アクセス制御（Delegated RBAC / 2層ユーザー管理）
* **入力**：編集長（Editor）または最高管理者（Admin）によるユーザー追加、情報・役職更新、パスワード再発行、利用停止・再開、アカウント削除操作
* **処理**：
  * **編集長へのユーザー管理権限委譲**: 編集長（Editor / 部門管理者）は、自部署の日常的な人事異動・新入社員配属・PW再発行・退職停止をその場で完結できるよう、ユーザー管理機能（`USER_MANAGE`）にアクセス可能とする。
  * **委譲操作スコープ**:
    * 編集長は「👤 閲覧者（Viewer）」および「✏️ 編集長（Editor）」アカウントの追加・編集・PW再発行・利用停止・削除が可能。
    * 新規社員登録時、編集長の所属部署が初期値として自動補完される。
  * **権限昇格の絶対禁止（Privilege Escalation Prevention）**:
    * 編集長がアカウントを追加または更新する際、「👑 管理者（Admin）」ロールを指定・付与することは不可（UI選択肢から除外、API側で403 Forbidden遮断）。
  * **上位階層の不可侵・完全保護（Upper-Tier Immunity）**:
    * 編集長は「👑 管理者（Admin）」アカウントの編集、パスワード再発行、利用停止、削除を行うことは一切不可（UI上で「🔒 管理者保護」表示、API側で403 Forbidden遮断）。
  * **全社保守・監査分離**:
    * システム設定・AIモデル設定・全社操作監査ログ閲覧は最高管理者（Admin）専用を維持し、編集長には公開しない。
* **受入条件**：
  * **AC-034-01**：編集長（Editor）が「👤 閲覧者（Viewer）」および「✏️ 編集長（Editor）」のアカウント作成、情報変更、パスワードリセット、利用停止、削除を正常に実行できること。
  * **AC-034-02**：編集長（Editor）が「👑 管理者（Admin）」のアカウントを編集、パスワードリセット、利用停止、削除しようとした場合、確実に403 Forbiddenで遮断され変更されないこと。
  * **AC-034-03**：編集長（Editor）が新規ユーザー登録または役職変更において `role="admin"` を指定した場合、権限昇格防止ガードにより確実に403 Forbiddenで遮断されること。
  * **AC-034-04**：WebUIのユーザー一覧テーブルにおいて、編集長ログイン時は管理者アカウントに「🔒 管理者保護」が表示され、モーダル選択肢から「👑 管理者」が安全に除外されること。

### REQ-035: ブルートフォース総攻撃防護（アカウントロックアウト）＆セッションアイドルタイムアウト
* **入力**：ユーザーログイン試行（ユーザー名、パスワード）、APIリクエスト（Bearerトークン）、管理者/部門管理者によるアンロック操作
* **処理**：
  * **ブルートフォース連続失敗検知**: 同一アカウントで連続5回パスワード照合に失敗した場合、5分間（300秒）アカウントを一時ロック。ロック中の試行は照合せず即座に403遮断。
  * **自動復帰**: 5分経過後は正しいパスワードで自動復帰し失敗カウントを0にリセット。
  * **即時アンロック**: 管理者または自部署の編集長が管理画面/API経由で即時アンロック可能。
  * **無操作アイドルタイムアウト**: APIリクエストごとに `session.touch()` で更新し、最終操作から30分以上無操作だった場合セッションを破棄して401 Unauthorized返却。
* **受入条件**：
  * **AC-035-01**：同一アカウントで5回連続失敗時に5分間一時ロックされ、ログインが遮断されること。
  * **AC-035-02**：5分経過後に正しいパスワードでログインが成功し失敗カウントがリセットされること。
  * **AC-035-03**：管理者および部門管理者がロック中のアカウントを即時アンロックできること。
  * **AC-035-04**：最終操作から30分無操作でセッション失効となり自動ログアウトされること。

### REQ-036: 全画面多言語化（i18n）および国際化レイアウト可読性最適化
* **入力**：言語選択ドロップダウン操作（日本語 `ja` / 英語 `en` / 繁体字中国語 `zh-TW`）、`localStorage` 保存値
* **処理**：3言語完全辞書エンジン（`src/web/static/i18n.js`）およびフレーズテーブル（`i18n_phrases.js`）、DOM走査、MutationObserver、レイアウト安全CSS（`word-break`, `:lang(zh-TW)` 専用フォント/行間）。
* **受入条件**：
  * **AC-036-01**：ヘッダー等の言語切替ドロップダウンで全画面テキストが即座に切り替わること。
  * **AC-036-02**：選択言語が `localStorage` に保存され、ブラウザ再読込後も維持されること。
  * **AC-036-03**：英語・繁体字中国語表示時に文字切れ・枠外はみ出し・レイアウト崩れが一切発生しないこと。
  * **AC-036-04**：動的トースト通知、モーダルダイアログ、テーブルヘッダー、各種バッジも正確に翻訳されること。

### REQ-037: 全面セキュリティ脆弱性対策・ゼロトラスト防護
* **入力**：外部APIリクエスト、Google OIDC IDトークン、JSONリクエストボディ、一般社員による一覧照会
* **処理**：
  1. **開発用エンドポイント保護**: `POST /api/v1/auth/switch` を本番環境でデフォルト無効化（403 Forbidden）。`ALLOW_DEV_SWITCH="true"` のみ許可。
  2. **Google OIDC IDトークン暗号署名検証**: `google.oauth2.id_token.verify_oauth2_token` によりGoogle公式公開鍵（JWKS）を用いたRSA署名検証を必須化（未署名JWT遮断）。
  3. **Stored DOM XSS根絶**: 管理画面のインライン `onclick` 文字列結合を全廃し、`data-username` 属性とイベントデリゲーションへ移行。
  4. **タイミング攻撃防御**: 存在しないユーザー名での認証試行時にもダミーPBKDF2計算（100,000反復）を実行し、応答時間差によるユーザー列挙を防止。
  5. **リクエストサイズ制限**: `MAX_PAYLOAD_SIZE = 25MB` を超えるリクエストを 413 Payload Too Large で即時遮断。
  6. **センシティブ情報マスキング**: 一般社員（Viewer）からの社員一覧照会時、人事メモ（`notes`）、失敗回数（`failed_attempts`）、ロック状態（`is_locked`）を強制マスキング。
  7. **設定ファイル保護・セキュリティヘッダー**: `system_settings.json` のパーミッションを `0600` に強制設定。全レスポンスに `Content-Security-Policy` および `Permissions-Policy` を送出。
* **受入条件**：
  * **AC-037-01**：環境変数が未設定の場合、開発用switchエンドポイントが403 Forbiddenで遮断されること。
  * **AC-037-02**：本番モードにおいて、未署名または不正署名のGoogle IDトークンが確実に拒絶されること。
  * **AC-037-03**：管理画面の全モーダル起動・操作において、インラインスクリプトを用いずデータ属性経由で安全に動作すること。
  * **AC-037-04**：存在しないユーザーへの認証試行が一定の計算時間（ダミーハッシュ）を要して応答すること。
  * **AC-037-05**：25MBを超えるリクエストボディが413 Payload Too Largeで即時遮断されること。
  * **AC-037-06**：一般社員からの社員一覧取得時に人事メモやロック状態が開示されないこと。
  * **AC-037-07**：設定ファイルが0600で保存され、レスポンスにセキュリティヘッダーが含まれること。

### REQ-038: 大企業NAT対応・動的レート制限管理
* **入力**：ログインAPI・チャットAPIへのアクセスリクエスト、管理画面からのレート制限設定変更
* **処理**：
  1. **ログインAPIタイマー**: 60秒スライディングウィンドウ方式で試行を追跡。超過時は `Retry-After: <秒数>`（最古記録が外れるまでの残り時間）を返却。
  2. **チャットAPIのアカウント単位分離**: 10,000人規模の大企業で単一NAT/プロキシIPを共有している場合でも他社員を巻き添えにしないよう、`/api/v1/chat` の制限軸を `session.username`（ログインアカウント）に分離（デフォルト60回/分）。
  3. **プロキシクライアントIP抽出**: `X-Forwarded-For` ヘッダーからオリジンクライアントIPを正確に抽出。
  4. **管理画面動的設定**: `system_settings.json` / `/api/v1/settings`（GET/POST）により `rate_limit_login` および `rate_limit_chat`（`0` 設定で無制限化）をサーバー再起動不要で即時変更可能とする。
* **受入条件**：
  * **AC-038-01**：ログインAPI制限超過時に 429 Too Many Requests と有効な `Retry-After` ヘッダーが返却されること。
  * **AC-038-02**：同一IPから複数ユーザーがチャットAPIを利用した場合、ユーザーごとに独立した利用枠が維持されること。
  * **AC-038-03**：リバースプロキシ経由時に `X-Forwarded-For` から真のクライアントIPが取得できること。
  * **AC-038-04**：管理画面からレート制限の上限値を変更（または0で無制限化）でき、即時反映されること。

## 3. 追加要件の詳細と受入条件（Acceptance Criteria）

### REQ-008: クラウドGeminiハイブリッド推論
* **入力**：ユーザープロンプト、モデル指定（例: `gemini-2.0-flash`, `gemini-1.5-pro`）、APIキー
* **処理**：`InferenceEngine` に `provider="gemini"` を指定した場合、Google公式 `google-genai` SDK を通じてクラウドAPI推論を実行。未設定またはオフライン時はローカルLiteRT-LMで実行。
* **出力**：Geminiからの生成回答テキスト（ストリーミング対応）
* **受入条件**：
  * **AC-008-01**：`provider="gemini"` 指定時にGoogle GenAI APIクライアントを通じて回答が取得できること。
  * **AC-008-02**：APIキー未設定時またはオフライン時に適切な案内またはローカルモデルへのフォールバックが行われること。

### REQ-009: 文境界優先チャンキング
* **入力**：長文テキスト（日本語/英語）、目標チャンクサイズ（例: 500〜1200字）、オーバーラップ長
* **処理**：指定文字数の 65%〜100% の探索ウィンドウ内で、句点「。」「！」「？」および改行記号「\n\n」「\n」を探索して分割点を決定。各チャンクに見出しや位置情報（`locator`）を付与。
* **出力**：`ChunkDraft` オブジェクトのリスト
* **受入条件**：
  * **AC-009-01**：文の途中ではなく句点または改行でチャンクが分割されること。
  * **AC-009-02**：各チャンクに正確な文字オフセットと位置識別子（`locator`）が保持されること。

### REQ-010: ナレッジブロックCMS（部分文面CRUD）
* **入力**：ブロックID、更新後テキスト、新規追加テキスト、削除対象ブロックID
* **処理**：
  * **追加 (Create)**：新しい文面ブロックを登録し、即座にベクトル化してストアへ格納。
  * **取得 (Read)**：キーワードや文書IDでブロック一覧を検索・取得。
  * **更新 (Update)**：特定ブロックの文面のみを書き換え、該当ブロックのベクトルのみをミリ秒で再計算・置換。
  * **削除 (Delete)**：特定ブロックをベクトルストアから即座に削除。
* **受入条件**：
  * **AC-010-01**：部分文面を更新した直後の検索において、更新後の内容が即座にヒットし、古い内容がヒットしないこと。
  * **AC-010-02**：ブロック削除後に該当内容が検索対象から完全に除外されること。

### REQ-011: 人間中心設計（HCD）WebUI
* **入力**：ブラウザからのユーザー操作（クリック、ドラッグ＆ドロップ、テキスト入力）
* **処理**：
  * 明快な5大タブ構成：
    1. 💬 **社内アシスタント（チャット）**：ChatGPT互換、厳選1行出典リンク表示。
    2. 📁 **ファイル追加**：D&D対応、自動解析・自動チャンキング。
    3. ✏️ **ナレッジ文面編集**：カード型ブロックエディタで部分修正・即時保存。
    4. 🔍 **検索テスト（シミュレーター）**：質問文に対するヒットチャンクとスコアの可視化。
    5. ⚙️ **モデル設定**：ローカル（LiteRT-LM）とクラウド（Gemini API）のワンタッチ切替。
* **受入条件**：
  * **AC-011-01**：WebUIが単一ポート（FastAPI内包）で起動し、ブラウザから主要5機能が正常に操作できること。
  * **AC-011-02**：ボタンや操作ごとに成功トースト通知・エラー通知が表示され、直感的に状況が把握できること。

### REQ-012: MCP (Model Context Protocol) サーバー
* **入力**：外部MCPクライアント（Claude Desktop, Cursor, OpenClaw等）からの `tools/list` および `tools/call`
* **処理**：`search_knowledge` ツール（引数: `query`, `limit`）を公開し、社内RAG検索結果を構造化データとして返却。
* **出力**：MCP規格に準拠したJSONレスポンス
* **受入条件**：
  * **AC-012-01**：MCPエンドポイントに対してツール一覧要求を送信した際、`search_knowledge` ツールが取得できること。
  * **AC-012-02**：`search_knowledge` ツール呼び出しで上位チャンクと出典がMCPフォーマットで返却されること。

### REQ-013: 多階層ロールベースアクセス制御（RBAC）およびセキュア認証
* **入力**：ユーザーセッショントークン（Header / Cookie）または認証資格情報
* **処理**：
  * ロール階層の定義：
    1. **Viewer（一般社員）**：チャット閲覧・対話のみ可能。ナレッジ登録・編集、モデル変更、システム設定は全て不可（UI非表示＆API拒否）。
    2. **Editor（部門長 / 編集担当）**：チャット＋ナレッジ追加・文面ブロック編集・削除、検索シミュレータ利用可能。モデル変更やシステム設定、APIキー設定は不可。
    3. **Admin（最高権限 / システム管理者）**：全操作（チャット、ナレッジ操作、モデル選択・ダウンロード、APIキー設定、システム設定、ユーザー管理）が可能。
  * 将来的に多数の部門・役職（経理部門長、人事部門長、法務監査役等）を容易に追加・拡張できる柔軟な権限マッピング機構。
* **受入条件**：
  * **AC-013-01**：Viewerロールはチャットのみ実行可能であり、ナレッジ変更やシステム設定のAPI要求に対して HTTP 403 Forbidden が返却されること。
  * **AC-013-02**：EditorロールはナレッジCRUDが可能であり、モデル変更やAPIキー設定要求に対して HTTP 403 Forbidden が返却されること。
  * **AC-013-03**：Adminロールは全機能が実行可能であること。
  * **AC-013-04**：未認証アクセスに対して HTTP 401 Unauthorized または適切な認証要求が行われること。

### REQ-014: Lite版モデルデフォルト選定および新モデル動的自動取得
* **入力**：Gemini APIキーまたはモデル一覧取得要求
* **処理**：
  * クラウドGeminiの初期デフォルトモデルを無料枠で利用可能なLite版（`gemini-2.0-flash-lite` 等）に設定。
  * Google公式 GenAI SDK の `client.models.list()` を用いて、利用可能な最新モデル一覧を動的取得するエンドポイント（`GET /api/v1/models/available`）を提供。
  * 将来Googleが新モデルをリリースした際、コード修正なしで一覧を自動同期し、カスタムモデル直接指定も受け付ける。
* **受入条件**：
  * **AC-014-01**：初期設定において無料枠優先のLite版モデルがデフォルト選定されていること。
  * **AC-014-02**：新モデル動的取得APIにより、将来の追加モデルをプログラム改修なしで自動取得・選択可能であること。
  * **AC-014-03**：カスタムモデル名の手動入力指定に対応していること。

### REQ-015: ゼロトラスト・APIキー完全秘匿およびセキュリティ保護
* **入力**：APIキー設定要求、ログ出力、ナレッジ参照要求
* **処理**：
  * APIキーをブラウザ側LocalStorageに平文保存させず、サーバーセッション/環境変数でセキュアに保持。
  * 設定確認APIではマスク形式（`AIzaSy...****`）のみをAdminに限定返却。
  * サーバー側ログおよび例外スタックトレースにおいてAPIキー文字列を自動マスク・サニタイズ。
  * パストラバーサルおよび入力インジェクションの多層防御。
* **受入条件**：
  * **AC-015-01**：ブラウザ側ストレージに平文APIキーが一切漏洩せず、Admin以外にはマスク情報すら開示されないこと。
  * **AC-015-02**：ログ出力およびエラー通知においてAPIキー文字列が自動マスキングされること。
  * **AC-015-03**：パストラバーサルや不正なブロックIDの操作が厳格に遮断されること。

### REQ-016: GitHubリポジトリへの安全な初期同期
* **入力**：Gitリモート先 `git@github.com:your-org/GemmaCore_Mac.git`
* **処理**：
  * `.gitignore` により、AI内部指示（`.agents/`）、内部管理台帳（`docs/HANDOFF.md`, `docs/DECISIONS.md`, `docs/AUTONOMY.md` 等）、仮想環境（`litert-env/`）、モデルバイナリ、一時キャッシュ、秘密鍵・環境変数を完全除外。
  * 公開用ドキュメントおよび安全な実装ソースコードのみをGit初期化・コミット・プッシュ。
* **受入条件**：
  * **AC-016-01**：機密ファイル・内部台帳が `.gitignore` によりステージング対象から確実に除外されていること。
  * **AC-016-02**：指定されたGitHubリモートリポジトリに対して安全に同期完了すること。

### REQ-017: ChatGPT形式マルチセッション会話スレッド履歴管理
* **入力**：スレッド作成・選択・メッセージ送信・スレッド名称変更・スレッド削除要求
* **処理**：
  * 会話スレッドを永続化（スレッドID、タイトル、作成日時、更新日時、メッセージ配列）。
  * 最初の質問文からスレッドタイトルを自動命名。
  * WebUI左サイドバーで過去のチャットスレッド一覧を表示・選択・切り替え・削除可能。
* **受入条件**：
  * **AC-017-01**：複数スレッドが独立して作成・保存され、画面再読み込み後も過去の会話履歴が保持されていること。
  * **AC-017-02**：スレッドの個別削除および新規チャット開始が正常に動作すること。

### REQ-018: ユーザー権限動的付与管理＆高堅牢ログイン認証
* **入力**：管理者によるユーザー追加・権限（Viewer/Editor/Admin等）付与・パスワード設定、ユーザーログイン認証
* **処理**：
  * 管理者がWebUI上からユーザーアカウントを作成し、動的にロール（Viewer, Editor, Admin, カスタム役職）を割り当て・変更可能。
  * ソルト付きPBKDF2/SHA256ハッシュによるセキュアパスワード認証。
  * 将来的な生体認証・パスキー（WebAuthn/FIDO2）への移行に対応した拡張アーキテクチャ。
* **受入条件**：
  * **AC-018-01**：管理者がユーザーごとに権限を新規付与・変更でき、変更直後からアクセス制御に即時反映されること。
  * **AC-018-02**：セキュアログイン画面により正しい認証情報でのみセッションが確立されること。

### REQ-019: ユーザー別構造化監査証跡ログ（Audit Trail）
* **入力**：全API操作（ログイン、チャット対話、ナレッジ作成/変更/削除、モデル変更、権限付与）
* **処理**：
  * 「誰が（ユーザー名・役職）」「いつ（タイムスタンプ）」「どのIPから」「どの操作を実行し」「成否（SUCCESS/FORBIDDEN/ERROR）」を構造化JSONで自動記録。
  * 管理者画面で監査ログを検索・フィルタリング・確認可能。
* **受入条件**：
  * **AC-019-01**：ユーザー操作ごとに監査レコードが確実に生成・永続化されること。
  * **AC-019-02**：管理者画面からユーザー別・操作別の監査ログ一覧を閲覧・検索できること。

### REQ-020: システム詳細障害診断ログ（Diagnostics Log & Stack Trace）
* **入力**：システム内部イベント、エラー・例外発生、推論フォールバック
* **処理**：
  * 例外スタックトレース、実行レイテンシ、Qdrant状態、推論バックエンド状態を詳細記録（APIキーや秘密情報は自動マスク）。
* **受入条件**：
  * **AC-020-01**：障害発生時に原因調査に必要な詳細スタックトレースとエラーコンテキストが記録されること。
  * **AC-020-02**：診断ログ内からAPIキー等の秘密情報が漏洩しないこと。

### REQ-021: ログ保持期間設定（7日〜最大365日）および自動パージ機構
* **入力**：管理者によるログ保持期間設定（7日, 30日, 90日, 180日, 365日）
* **処理**：
  * 指定された保持期間を超過した監査ログおよびシステムログをバックグラウンドで自動的に削除・クリーンアップ。
* **受入条件**：
  * **AC-021-01**：設定画面からログ保持期間（最大1年間）を柔軟に変更・保存できること。
  * **AC-021-02**：保持期間を超過した古いログレコードが自動的に安全パージされること。

### REQ-022: 未ログイン状態のUI完全遮断＆API厳格認証（Strict Authentication Gate）
* **入力**：未認証ユーザーによるWebUIアクセス、認証トークンなしのREST API呼び出し

    * ログイン成功時、失敗カウント（`failed_attempts`）およびロック期限（`locked_until`）は直ちに0/Noneにリセット。
  * **管理者・部門管理者による即時アンロック**:
    * 最高管理者（Admin）または部門管理者（Editor / 委譲RBACルール準拠）がWebUIの「🔓 ロック解除」ボタンまたはAPI `POST /api/v1/users/{username}/unlock` を実行することで、5分を待たずに即時アンロック可能。
    * 監査ログに `action="USER_UNLOCK"`, `status="SUCCESS"` を記録。
  * **セッション無操作（アイドル）タイムアウト**:
    * ログイン後のセッション最大有効期限（24時間）に加え、各セッションの最終操作日時（`last_activity_at`）を管理。
    * ユーザーが操作（任意のAPIリクエスト）を行うたびに `last_activity_at` を現在時刻に更新（`session.touch()`）。
    * 最後の操作から30分（1800秒）以上無操作の状態でAPIアクセスが行われた場合、セッション失効（`is_expired() == True`）として扱い、401 Unauthorizedを返却。
    * フロントエンドは「30分間操作がなかったため、セキュリティ保護のため自動ログアウトしました」と通知し、安全にログイン画面へ遷移。
* **受入条件**：
  * **AC-035-01**：同一ユーザーアカウントに対しパスワード認証を連続5回失敗した場合、自動で5分間アカウントが一時ロックされ、その間のログイン試行が確実に遮断されること。
  * **AC-035-02**：アカウントロックから5分が経過した後、正しいパスワードでログインが成功し、失敗カウントが0にリセットされること。
  * **AC-035-03**：最高管理者（Admin）または部門管理者（Editor、自部署の対象）が管理画面またはAPI経由でロック中のアカウントを即時アンロックできること。
  * **AC-035-04**：ログイン後、最後の操作から30分以上無操作だった場合、セッション失効となり再ログインが要求されること。ログインから24時間の絶対有効期限も継続して有効であること。

### REQ-036: 全画面多言語化（i18n）および国際化レイアウト可読性最適化
* **入力**：ヘッダー言語選択ドロップダウン操作（日本語 `ja` / 英語 `en` / 繁体字中国語 `zh-TW`）、`localStorage` 保存値、DOM属性バインディング (`data-i18n`, `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-html`)
* **処理**：
  * **3言語完全辞書エンジン (`src/web/static/i18n.js`)**: 日本語（`ja`）、英語（`en`）、繁体字中国語（`zh-TW`）の辞書データを完全配備。ワンクリック言語切替および `localStorage.setItem('gcomm_lang', lang)` による永続保存。
  * **DOMおよび動的UI即時書き換え**: 静的HTML要素に加え、動的トースト通知、ダイアログ文面、テーブルヘッダー、動的バッジ、確認モーダルの全メッセージを `i18n.t(key)` 経由で即座に多言語へ書き換え。`CustomEvent('languageChanged')` を発行してリアルタイム更新。
  * **国際化レイアウト・可読性最適化**:
    * 英語表示時に単語長が拡大した場合でも、ボタン・カード・モーダル・ヘッダー・テーブルの枠からはみ出さない `word-break: break-word` / `overflow-wrap: break-word` / `flex-wrap: wrap` の自動折り返し設計。
    * 繁体字中国語表示時に文字の高さや行間が詰まらない `:lang(zh-TW)` 専用フォントファミリー（`PingFang TC`, `Microsoft JhengHei`）および `line-height: 1.7` の視認性調整。
* **受入条件**：
  * **AC-036-01**：ヘッダー等の言語切り替えドロップダウンにより、全画面のUIテキストが即座に日本語・英語・繁体字中国語へ切り替わること。
  * **AC-036-02**：選択した言語設定が `localStorage` に保存され、ブラウザ再読み込み後も設定が維持されること。
  * **AC-036-03**：英語や繁体字中国語への切り替え時において、文字切れ、枠外へのはみ出し、レイアウト崩れが一切発生せず快適に閲覧・操作できること。
  * **AC-036-04**：動的に生成されるトースト通知、モーダルダイアログ、テーブルヘッダー、各種ステータスバッジも選択言語に従って正確に切り替わること。
